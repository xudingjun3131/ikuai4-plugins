## 逐条详情

### TC-01 引擎启停与端口 — PASS
- 停止前：18080/18081/18082 三端口 OPEN，`/api/health` = `{"ok":true,...}`。
- 浏览器点「停止引擎」后：三端口全部 CLOSED，health 不通，徽标「已停止」，按钮变「启动引擎」。
- 点「启动引擎」后：三端口恢复 OPEN，`{"paused":false}`。

### TC-02 关闭抓包必须真停 — PASS
- 开启态发 `/on1`~`/on3`，落库 3 条。
- 点「关闭抓包」后 `capture={"paused":true}`；再发 `/off1`~`/off5`，逐条核对 flow 列表：**5 条全部未落库**（总数里的增量是「pc」设备的 Chrome-sync/Telegram 后台流量，非本次显式代理请求）。徽标「抓包已关」。历史 BUG 已修复。

### TC-03 开关与启动对齐 — PASS
- 保持关闭抓包状态，停引擎→启引擎：`capture` 仍为 `{"paused":true}`；发 3 条请求后 flow 全部未记录。无静默恢复记录问题。

### TC-04 三态显示 — PASS
- 抓包已关（徽标「抓包已关」/`paused:true`）→ 开启抓包（「抓包中」/`paused:false`）→ WebUI 顶栏点暂停（引擎侧「已暂停」、按钮变「继续」）。刷新插件页徽标显示「已暂停(引擎)」。三态正确。

### TC-05 规则编辑器 12 类型 — PASS
- 「新建」类型下拉含全部 12 种：内容替换/头改写/本地文件映射/镜像远端/上游网关/二级代理/反向代理/拦截域名/放行域名/访问控制/不解密(SSL绕过)/高亮标记。
- 表单随类型切换（选「头改写」出现阶段/设置键值对/删除头；选「内容替换」出现阶段/查找/替换为）。
- 非法正则 `[/api/(` 点保存被拒，页面明确报错「路径不是合法正则: [/api/(」。
- 规则可新建（实测创建 body_replace 规则成功）、有类型徽标+摘要、可启停（点开关 title 在「启用/停用」间切换）、可改可删（DELETE /api/rules/<id> 返回 204）。

### TC-06 内置规则 10 条 — PASS
- 当前 10 条：`builtin-no-cache` / `builtin-accept-encoding` / `builtin-cors` / `builtin-strip-csp` / `builtin-hl-api` / `builtin-hl-telemetry-{clarity,ga,gtm,dc}` / `builtin-hl-static`，均有「内置」角标。
- 有「内置」一键载入按钮（title 注明「整包替换当前规则」）；accept-encoding 开关实测可从停用→启用。

### TC-07 改包再转发 — PASS（核心需求）
- 启用 `builtin-accept-encoding`，新建内容替换规则（path `^/api/`，阶段响应，bird→BIRD）。
- `curl -x 代理 http://10.10.10.5:19130/api/saybird` 结果：
  - 客户端收到 `{"say":"BIRD",...}`（改写后内容）
  - 上游收到 `Accept-Encoding: identity`、`Test-Header: BIRD`、`Content-Length` 自动修正
  - 引擎 flow 详情里存的响应体也是改写后的 BIRD
- 改包再转发确实生效。

### TC-08 压缩响应边界 — PASS（符合预期，非缺陷）
- 用遵循 Accept-Encoding 的 gzip 上游（:19131）测试：
  - (a) 停用 identity 规则：上游返回 gzip，明文替换**不生效**（响应仍 `bird`）——hook 层拿到压缩字节，属边界约束。
  - (b) 启用 identity 规则：代理请求头变 `Accept-Encoding: identity`（flow 中确认从 `deflate, gzip` → `identity`），上游返回明文，替换**生效**（`BIRD`）。
- 测试方记「符合预期」，不记缺陷。

### TC-11 断点拦截 — **FAIL**
- 用特定 host 测试：`PUT /api/breakpoints {"enabled":true,"match":{"host":"10.10.10.5"}}`，发请求后正常出现 **phase=request** 会话（id `4ffc48de...`），前台 curl 挂起不返回，说明断点功能本身可用；`POST /resume` 返回 `{"status":"resumed"}`。
- 但用文档要求的 **host=`"*"`** 全匹配测试（重复两次，分别等待 3s/4s）：**没有任何会话产生，请求直接放行通过**，客户端立刻收到完整响应。
- 文档明确写「2026-11-17 修复：breakpoint 的 hostMatch 漏了 `*` 特判，'全匹配'断点此前从来没反应」——**本版本该修复未生效**，全匹配断点依旧无响应。
- 测试结束已 `PUT {"enabled":false,"match":{}}` 关闭断点。
- **FAIL 用例附证据**：
  - `PUT /api/breakpoints {"enabled":true,"match":{"host":"*"}}` → 200，确认返回 `{"enabled":true,"match":{"host":"*"}}`
  - `curl -x 代理 http://10.10.10.5:19130/bp-test` → 3s 后 `GET /api/breakpoints` sessions=0，客户端已拿到 `{"say":"bird","path":"/bp-test",...}`
  - 对照：`host":"10.10.10.5"` 时 sessions=1（phase=request），证明仅 `*` 特判缺失。
